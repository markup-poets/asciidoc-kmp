== Chapter 1: Getting Started with Kotlin Multiplatform

Kotlin Multiplatform (KMP) allows you to share code between different platforms while maintaining the flexibility to write platform-specific code when needed.

=== Why Choose KMP?

There are several compelling reasons to use Kotlin Multiplatform:

* Code Reusability: Write business logic once, use everywhere
* Type Safety: Leverage Kotlin's strong type system
* Native Performance: Compile to native code for each platform
* Gradual Adoption: Start small and expand shared code over time

=== Setting Up Your First Project

To get started with KMP, you'll need:

* Kotlin 2.0 or newer
* Gradle build system
* Platform-specific SDKs (Android SDK, Xcode for iOS)

Here's an example of common code:

----
// Example: Common code
expect fun getPlatformName(): String

fun greet(): String {
    return "Hello from ${getPlatformName()}!"
}
----

=== Project Structure

A typical KMP project follows this structure:

----
project/
├── commonMain/     # Shared code
├── androidMain/    # Android-specific
├── iosMain/        # iOS-specific
└── jvmMain/        # JVM-specific
----

This modular structure keeps platform-specific code isolated while maximizing code sharing.

=== Your First Shared Function

Let's create a simple function that works across all platforms:

----
// In commonMain
fun calculateFibonacci(n: Int): List<Int> {
    if (n <= 0) return emptyList()
    if (n == 1) return listOf(0)
    
    val sequence = mutableListOf(0, 1)
    for (i in 2 until n) {
        sequence.add(sequence[i-1] + sequence[i-2])
    }
    return sequence
}
----

This function works identically on Android, iOS, JVM, and native platforms!

Start with pure business logic in commonMain before adding platform-specific features.
