== Chapter 2: Advanced Techniques

Once you're comfortable with the basics, you can explore more advanced KMP patterns and techniques.

=== Expect/Actual Declarations

The `expect`/`actual` mechanism is the foundation of platform-specific code in KMP.

==== Common Code (expect)

In your `commonMain` source set:

[source,kotlin]
----
// Declare what you expect each platform to provide
expect class PlatformLogger {
    fun log(message: String)
}

expect fun currentTimeMillis(): Long
----

==== Platform Implementation (actual)

In `androidMain`:

[source,kotlin]
----
actual class PlatformLogger {
    actual fun log(message: String) {
        android.util.Log.d("MyApp", message)
    }
}

actual fun currentTimeMillis(): Long {
    return System.currentTimeMillis()
}
----

In `iosMain`:

[source,kotlin]
----
actual class PlatformLogger {
    actual fun log(message: String) {
        NSLog(message)
    }
}

actual fun currentTimeMillis(): Long {
    return NSDate().timeIntervalSince1970.toLong() * 1000
}
----

=== Dependency Injection

For larger projects, consider using dependency injection to manage platform-specific implementations:

[source,kotlin]
----
// Common interface
interface FileSystem {
    fun readFile(path: String): String
    fun writeFile(path: String, content: String)
}

// Inject platform-specific implementation
class DocumentProcessor(
    private val fileSystem: FileSystem
) {
    fun processDocument(path: String): String {
        val content = fileSystem.readFile(path)
        return content.uppercase()
    }
}
----

IMPORTANT: Keep platform-specific code minimal. Most of your logic should be in `commonMain`.

=== Testing Across Platforms

Write tests in `commonTest` that run on all platforms:

[source,kotlin]
----
class CalculatorTest {
    @Test
    fun testAddition() {
        val result = Calculator.add(2, 3)
        assertEquals(5, result)
    }
    
    @Test
    fun testFibonacci() {
        val sequence = calculateFibonacci(5)
        assertEquals(listOf(0, 1, 1, 2, 3), sequence)
    }
}
----

These tests automatically run on JVM, Android, iOS, and other configured platforms.

=== Performance Considerations

When working with KMP, keep these performance tips in mind:

* Minimize platform boundary crossings
* Use inline functions for small, frequently-called code
* Profile on each target platform
* Consider platform-specific optimizations when needed

[source,kotlin]
----
// Inline functions avoid overhead
inline fun <T> measureTime(block: () -> T): Pair<T, Long> {
    val start = currentTimeMillis()
    val result = block()
    val duration = currentTimeMillis() - start
    return result to duration
}
----

=== Best Practices Summary

Here's a quick reference for KMP best practices:

[cols="1,2"]
|===
|Practice |Description

|Maximize shared code
|Put as much logic as possible in `commonMain`

|Minimize expect/actual
|Use only when truly platform-specific

|Test thoroughly
|Run tests on all target platforms

|Document platform differences
|Clearly explain why platform-specific code exists

|Use interfaces
|Prefer interfaces over expect/actual when possible
|===

WARNING: Avoid premature optimization. Start with shared code and only add platform-specific implementations when measurements show it's necessary.

=== Real-World Example

Here's a complete example of a cross-platform HTTP client:

[source,kotlin]
----
// commonMain
interface HttpClient {
    suspend fun get(url: String): String
}

class ApiService(private val client: HttpClient) {
    suspend fun fetchUserData(userId: String): User {
        val json = client.get("https://api.example.com/users/$userId")
        return Json.decodeFromString(json)
    }
}

// androidMain
actual class HttpClient {
    actual suspend fun get(url: String): String {
        return withContext(Dispatchers.IO) {
            URL(url).readText()
        }
    }
}

// iosMain
actual class HttpClient {
    actual suspend fun get(url: String): String {
        // Use NSURLSession
        return suspendCoroutine { continuation ->
            // iOS-specific implementation
        }
    }
}
----

This pattern allows you to write business logic once while using platform-native networking libraries.
