= Plugin ABI v1

A Markup Poet plugin is a WebAssembly module executed by the Chasm runtime.
A plugin is pure compute over JSON envelopes (no filesystem, no network, no
clock). *No host functions are available*: the only imports a module may
declare are the inert WASI functions listed under <<imports>>, and a module
importing anything else is rejected at load. This page is the normative ABI; for a walkthrough see
xref:how-to/write-a-wasm-plugin.adoc[Write a WASM plugin].

== Required exports

[cols="1,2,2"]
|===
|Export |Signature |Purpose

|`memory` |linear memory |Shared data buffer
|`plugin_alloc` |`(i32 size) -> i32 ptr` |Host asks the plugin to reserve memory
|`plugin_dealloc` |`(i32 ptr, i32 size)` |Host returns memory to the plugin
|`plugin_info` |`() -> i32 ptr` |Returns the descriptor payload
|`process` |`(i32 ptr, i32 len) -> i32 ptr` |Handles one invocation; `0` = internal failure
|`on_load` |`()` |Optional init hook
|`on_unload` |`()` |Optional shutdown hook
|`_initialize` |`()` |Optional; WASI reactor start-up, called once before any other export
|===

A returned pointer of `0` always means failure, so a plugin must never hand
out a buffer at address 0.

[#imports]
== Allowed imports

Modules built by WASI toolchains (Kotlin/Wasm `wasmWasi`, for one) import
functions from `wasi_snapshot_preview1` even when the plugin does no I/O. The
host provides these and only these, as stubs without effect:

[cols="2,3"]
|===
|Function |Stub behavior

|`fd_write`, `fd_close` |Report success; output is discarded
|`fd_read`, `fd_seek`, `fd_fdstat_get`, `fd_prestat_get`, `fd_prestat_dir_name` |Fail with `EBADF`
|`environ_sizes_get`, `environ_get`, `args_sizes_get`, `args_get` |Report success and write nothing
|`random_get`, `clock_time_get` |Fail with `ENOSYS`
|`proc_exit` |Returns without exiting
|===

None of them writes to plugin memory.

== Payload protocol

Every payload crossing the boundary is a *4-byte little-endian length prefix*
followed by *UTF-8 JSON*. Payloads are capped at *1 MB* (*64 KB* for the
descriptor); `PluginEngine(PluginLimits(...))` customizes the caps. The host
writes an invocation via `plugin_alloc` + memory writes, calls
`process(ptr, len)`, reads the length-prefixed response at the returned
pointer, then returns both buffers via `plugin_dealloc`. A plugin whose
invocation fails is *poisoned* and refuses further calls.

== Descriptor (`plugin_info`)

[source,json]
----
{
  "abiVersion": 1,
  "id": "shout-plugin",
  "name": "Shout",
  "version": "0.1.0",
  "description": "Uppercases the content of [shout] blocks",
  "capabilities": [ { "type": "block", "name": "shout" } ],
  "metadata": {}
}
----

Capability `type` is one of `block`, `blockMacro`, `inlineMacro`, `converter`.

== Invocation (host -> plugin)

[source,json]
----
{
  "abiVersion": 1,
  "extensionPoint": "block",
  "name": "shout",
  "attributes": { "1": "shout" },
  "content": "raw block body or macro target",
  "documentAttributes": { "toc": "" },
  "location": { "line": 12, "column": 1 },
  "backend": "html5"
}
----

* `attributes` carries the construct's own attributes: positional attributes
  keyed by their 1-based index plus the named attributes.
* For `blockMacro` and `inlineMacro`, the macro target is additionally
  available as `attributes["target"]`, and `content` is the target.
* For `block` and `blockMacro`, `attributes` also carries the block's `id`,
  `role` (roles separated by spaces), `options` (separated by commas) and
  `title` (as plain text) when the block has them. A named attribute of the
  same name takes precedence.
* For `converter`, `content` is the claimed node serialized as official ASG
  node JSON (see below).
* `backend` names the output format the host is producing; the HTML renderer
  sends `html5`. A plugin whose output suits only some formats declines the
  others (see <<declining>>). Hosts older than this field do not send it;
  treat a missing value as `html5`.

== Claiming built-in names

A `block`, `blockMacro`, or `inlineMacro` claim takes precedence over the
host's built-in handling of the same name:

* inline macros the renderer handles itself, such as `icon`, `stem`,
  `latexmath` and `asciimath`
* the block macros `video`, `audio` and `image`
* built-in block styles (`stem`, `source`, `listing`, `literal`, `verse`,
  `quote`, `pass`, `example`, `sidebar`) on leaf blocks

`toc` cannot be claimed.

== Response (plugin -> host)

[source,json]
----
{
  "ok": true,
  "replacement": { "contentType": "html", "value": "<div class=\"shout\">…</div>" },
  "warnings": [],
  "assets": [
    { "key": "shout-css", "placement": "head", "html": "<link rel=\"stylesheet\" href=\"shout.css\">" }
  ]
}
----

[cols="1,3"]
|===
|`contentType` |Host behavior

|`asciidoc`
|The host re-parses `value` and splices the resulting blocks (attribute substitution and macro expansion still apply)

|`html`
|Spliced as a raw passthrough block

|`asg`
|Official ASG node JSON: `nodes` holds an array of nodes (a single node object is also accepted); the host falls back to parsing `value` as JSON when `nodes` is absent. Block context requires blocks, inline context inlines — a mismatch or malformed node JSON is treated like `ok: false`
|===

`ok: false` + `error`: the host leaves the original construct untouched and
surfaces the error as a processing warning.

[#declining]
=== Declining

`ok: true` without a `replacement` declines the construct. The host keeps
the original, reports nothing, and renders it as if no plugin had claimed
it. Use this for a construct the plugin does not handle (a `video::` target
that is a file, not a service id) or a `backend` it has no output for.

=== Assets

`assets` lists document-level resources the replacement depends on. Each has
a `key`, the `html` to place, and a `placement`; `head` (the document
`<head>`) is the only placement defined and the default. The host keeps one
asset per `key` for a document, however many responses carry it, and ignores
the assets of a response that replaced nothing. `WasmExtensions.apply`
returns them in `PluginProcessingResult.assets`; `headContent` is ready to
pass to `OutputOptions.headContent`. A host that renders a fragment places
them in its own page. Assets apply to `block`, `blockMacro`, and
`inlineMacro` responses.

== Converter invocations

A `converter` capability plugs into HTML rendering, not document processing.
The host registers it as a custom renderer under its capability name
(block style, e.g. `gallery`, or ASG node kind, e.g. `ListBlock` — style
wins). The invocation's `content` is the claimed node as official ASG node
JSON (the node-level encoding of `asciidoc-asg`'s
`AsgDocumentJsonSerializer`), and `documentAttributes` carries the resolved
document attributes.

The response *must* be `{ "contentType": "html", "value": "…" }`; the value
is emitted verbatim in the node's place. Any failure — `ok: false`, another
content type, or a node with no official ASG form — renders as nothing plus a
rendering warning.

== Host refusal rules

The host refuses to load a plugin when:

* `abiVersion != 1`
* the plugin `id` duplicates an already-loaded plugin
* a `(type, name)` capability claim duplicates an existing one
* the module declares an import other than the <<imports,allowed WASI stubs>>
* a payload exceeds the configured cap
