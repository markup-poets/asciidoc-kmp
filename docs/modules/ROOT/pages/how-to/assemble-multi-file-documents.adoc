= Assemble multi-file documents

This page shows how to resolve an Antora-style multi-file document — includes and resource coordinates such as `partial$intro.adoc` — into a single flat AsciiDoc file.

NOTE: This documentation site is itself an Antora component; the assembly modules described here are dogfooded on the very structure you are reading.

== Prerequisites

* A document tree with an index file whose `include::[]` directives reference the other files, either by relative path or by Antora resource coordinate.
* For library use, the two assembly modules:

[source,kotlin,subs="attributes+"]
----
dependencies {
    implementation("{maven-group}:antora-resolution:{artifact-version}")
    implementation("{maven-group}:antora-assembler:{artifact-version}")
}
----

== Assemble with the wrapper script

From the project root:

[source,bash]
----
./assemble-article.sh my-article/index.adoc my-article/assembled.adoc
----

The script builds `:antora-assembler` and writes the fully resolved document to the output path.

== Assemble from the command line

For more control than the wrapper script gives, invoke the CLI directly. Build the JAR first:

[source,bash]
----
./gradlew :antora-assembler:jvmJar     # lands in antora-assembler/build/libs/
----

[source,bash]
----
java -cp antora-assembler/build/libs/antora-assembler-jvm-<version>.jar \
  org.markup.poet.antora.assembler.cli.MainKt \
  docs/modules/ROOT/pages/index.adoc output.adoc --component-root docs
----

[cols="1,2"]
|===
|Option |Effect

|`--component-root <path>`
|the Antora component root (default: the current directory)

|`--max-depth <n>`
|maximum include recursion depth (default: 50)

|`--no-preserve-comments`
|drop comments instead of preserving them

|`--allow-missing`
|continue when an include is missing, instead of failing

|`--allow-circular`
|continue when a circular dependency is found, instead of failing

|`-h`, `--help`
|show usage
|===

The two `--allow-*` flags exist because a partial assembly is sometimes more useful than none — when diagnosing a broken tree, for instance. They default to failing, so a broken document never passes silently.

Exit code is `0` on success and `1` when assembly failed.

== Assemble programmatically

The pipeline has two layers. `antora-resolution` turns coordinates into file paths; `antora-assembler` walks the include graph and merges content.

Key types:

* `ResourceCoordinate.parse(...)` (`org.markup.poet.antora`) — parses `type$path`, `module:type$path`, and `component:module:type$path` forms (`partial$`, `example$`, `page$`, `image$`, `attachment$`), falling back to a relative path.
* `AntoraResolver` / `DefaultAntoraResolver` — resolves a coordinate or include path against a `ResolutionContext`.
* `DocumentAssembler` / `DefaultDocumentAssembler` (`org.markup.poet.antora.assembler`) — parses the index file, resolves every include recursively, and merges the content.
* `AssemblerConfig` — index file, output file, component root, and safety knobs.

[source,kotlin]
----
val fileSystem = DefaultFileSystemAccess()
val assembler = DefaultDocumentAssembler(
    parser = DefaultAsciidocParser(),
    resolver = DefaultAntoraResolver(fileSystem),
    fileSystem = fileSystem
)

val result = assembler.assemble(
    AssemblerConfig(
        indexFile = "my-article/index.adoc",
        outputFile = "my-article/assembled.adoc",
        componentRoot = "my-article",
        maxDepth = 50,                       // include nesting limit
        failOnMissingIncludes = true,
        failOnCircularDependencies = true
    )
)

if (!result.success) {
    result.errors.forEach { println("${it.errorType}: ${it.message}") }
}
----

`AssemblerResult` reports the output path, the set of included files, and any errors (`INCLUDE_NOT_FOUND`, `CIRCULAR_DEPENDENCY`, `MAX_DEPTH_EXCEEDED`, ...) and warnings.

== Feed the result onward

The assembled file is ordinary AsciiDoc: render it with `html-cli`, export its ASG to DOT, or process it with any other tool in the pipeline.
