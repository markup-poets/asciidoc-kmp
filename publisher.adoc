= Publishing Your Article to HTML
:toc: left
:toclevels: 3
:icons: font

== Introduction

This guide shows you how to convert your multi-file AsciiDoc article into a single HTML document. Perfect for authors who want to organize their content across multiple files and folders.

== What You Need

=== Required Software

* *Java 11 or newer* - Check with `java -version`
* *Graphviz* (optional, for visualizing document structure)

=== Your Article Structure

Your article can be organized like this:

----
article1/
├── index.adoc           # Main article file
├── chapter1.adoc        # First chapter
├── chapter2.adoc        # Second chapter
└── images/              # Image folder
    ├── diagram.png
    └── photo.jpg
----

== Step 1: Organize Your Files

=== Create the Main Index File

Create `index.adoc` as your article's entry point:

[source,asciidoc]
----
= My Article Title
Author Name <author@example.com>
:toc: left
:icons: font

== Introduction

This is my introduction.

\include::chapter1.adoc[]

\include::chapter2.adoc[]

== Conclusion

Final thoughts here.
----

=== Create Chapter Files

Create `chapter1.adoc`:

[source,asciidoc]
----
== Chapter 1: Getting Started

This is the first chapter content.

image::images/diagram.png[Diagram,600]

Some more text here.
----

Create `chapter2.adoc`:

[source,asciidoc]
----
== Chapter 2: Advanced Topics

This is the second chapter.

image::images/photo.jpg[Photo,400]

More content follows.
----

== Step 2: Build the Tools

From the project root directory, build the necessary tools:

[source,bash]
----
# Build the document assembler
./gradlew :antora-assembler:jvmJar

# Build the HTML renderer (when available)
./gradlew :html-renderer:jvmJar
----

== Step 3: Assemble Your Document

Combine all your files into a single AsciiDoc document:

[source,bash]
----
java -cp antora-assembler/build/libs/antora-assembler-jvm-1.0.0.jar \
  org.markup.poet.antora.assembler.cli.MainKt \
  article1/index.adoc \
  article1/assembled.adoc
----

This creates `article1/assembled.adoc` with all includes resolved.

=== What This Does

* Reads your `index.adoc` file
* Finds all `include::` directives
* Merges all referenced files into one document
* Preserves image references
* Maintains document structure

== Step 4: Convert to HTML

=== Option A: Using the Complete Workflow Script (Recommended)

The easiest way is to use the provided script that does everything:

[source,bash]
----
./publish-to-html.sh article1/index.adoc article1/output.html
----

This script:
1. Builds the assembler
2. Assembles your multi-file document
3. Converts to HTML using AsciiDoctor

=== Option B: Using AsciiDoctor Directly

If you have AsciiDoctor installed:

[source,bash]
----
# Install AsciiDoctor (one-time setup)
gem install asciidoctor

# Convert to HTML
asciidoctor article1/assembled.adoc
----

This creates `article1/assembled.html`.

=== Installing AsciiDoctor

If AsciiDoctor is not installed:

[source,bash]
----
# macOS
brew install asciidoctor

# Linux (Ubuntu/Debian)
sudo apt-get install asciidoctor

# Any platform with Ruby
gem install asciidoctor

# Verify installation
asciidoctor --version
----

=== Option C: Online Converters

If you don't want to install AsciiDoctor, use online tools:

* https://asciidoclive.com/
* https://www.browserling.com/tools/asciidoc-to-html

Simply upload your `assembled.adoc` file.

== Step 5: View Your HTML

Open the generated HTML file in your browser:

[source,bash]
----
# macOS
open article1/assembled.html

# Linux
xdg-open article1/assembled.html

# Windows
start article1/assembled.html
----

== Complete Example

Here's a complete workflow from start to finish:

[source,bash]
----
# 1. Create your article structure
mkdir -p article1/images
cd article1

# 2. Create index.adoc (your main file)
cat > index.adoc << 'EOF'
= My First Article
John Doe
:toc: left

== Introduction
Welcome to my article.

\include::chapter1.adoc[]

\include::chapter2.adoc[]
EOF

# 3. Create chapter1.adoc
cat > chapter1.adoc << 'EOF'
== Chapter 1
First chapter content.
EOF

# 4. Create chapter2.adoc
cat > chapter2.adoc << 'EOF'
== Chapter 2
Second chapter content.
EOF

# 5. Add your images to the images/ folder
# (copy your PNG/JPG files here)

# 6. Go back to project root
cd ..

# 7. Use the complete workflow script
./publish-to-html.sh article1/index.adoc article1/output.html

# 8. Open in browser
open article1/output.html
----

=== Alternative: Step-by-Step

If you prefer to run each step manually:

[source,bash]
----
# Build the assembler
./gradlew :antora-assembler:jvmJar

# Assemble your document
./assemble-article.sh article1/index.adoc article1/assembled.adoc

# Convert to HTML (requires AsciiDoctor)
asciidoctor article1/assembled.adoc

# Open in browser
open article1/assembled.html
----

== Advanced Options

=== Allow Missing Files

If some included files don't exist yet:

[source,bash]
----
java -cp antora-assembler/build/libs/antora-assembler-jvm-1.0.0.jar \
  org.markup.poet.antora.assembler.cli.MainKt \
  article1/index.adoc \
  article1/assembled.adoc \
  --allow-missing
----

=== Set Maximum Include Depth

For deeply nested includes:

[source,bash]
----
java -cp antora-assembler/build/libs/antora-assembler-jvm-1.0.0.jar \
  org.markup.poet.antora.assembler.cli.MainKt \
  article1/index.adoc \
  article1/assembled.adoc \
  --max-depth 100
----

=== Visualize Document Structure

See your document's structure as a graph:

[source,bash]
----
# Convert to DOT format
./asciidoc2dot.sh article1/assembled.adoc

# Generate PNG visualization
dot -Tpng article1/assembled.dot -o article1/structure.png

# View the structure
open article1/structure.png
----

== Known Limitations

=== Block Attributes Not Supported

The parser currently does not support block attributes like `[source,kotlin]`. Using them will cause the assembler to hang.

*Workaround:* Use plain code blocks without attributes:

[source,asciidoc]
----
✅ Good (works):
----
fun hello() {
    println("Hello")
}
----

❌ Bad (causes hang):
[source,kotlin]
----
fun hello() {
    println("Hello")
}
----
----

The plain code blocks work perfectly and will be rendered correctly in HTML output.

== Troubleshooting

=== "File not found" Error

*Problem:* The assembler can't find your included files.

*Solution:* Check that:

* File paths in `include::` directives are correct
* Files exist in the specified locations
* You're running the command from the correct directory

=== Images Not Showing in HTML

*Problem:* Images appear as broken links.

*Solution:* 

* Ensure image paths are relative to the main document
* Use `image::images/photo.jpg[]` not absolute paths
* Keep images in a subfolder of your article directory

=== Java Not Found

*Problem:* `java: command not found`

*Solution:* Install Java 11 or newer:

[source,bash]
----
# macOS
brew install openjdk@11

# Ubuntu/Debian
sudo apt-get install openjdk-11-jdk

# Check installation
java -version
----

=== AsciiDoctor Not Found

*Problem:* `asciidoctor: command not found`

*Solution:* Install AsciiDoctor:

[source,bash]
----
# Using Ruby gems
gem install asciidoctor

# Or using package manager (macOS)
brew install asciidoctor

# Verify installation
asciidoctor --version
----

== Tips for Authors

=== Organize Your Content

* Use one file per chapter or major section
* Keep images in an `images/` subfolder
* Use descriptive filenames: `introduction.adoc`, `methodology.adoc`

=== Use Relative Paths

Always use relative paths for includes and images:

[source,asciidoc]
----
✅ Good:
include::chapter1.adoc[]
image::images/photo.jpg[]

❌ Bad:
include::/Users/john/article1/chapter1.adoc[]
image::/Users/john/article1/images/photo.jpg[]
----

=== Test Incrementally

After adding each chapter:

1. Assemble the document
2. Convert to HTML
3. Check that everything looks correct
4. Then add the next chapter

=== Keep a Backup

Before assembling, keep your original files safe:

[source,bash]
----
# Create a backup
cp -r article1 article1-backup
----
